Расхождения с VBA (риски паритета, по убыванию важности)
Дубль первой вершины в режиме Const. opor-polyline-points для замкнутой полилинии возвращает стартовую точку дважды (параметры 0 и N) — opor-geometry.lsp:112. В Var-режиме список дедупится, в Const — нет (opor-supports.lsp:79), а VBA всегда прогоняет equalpointsDel. Итог: на S1 будет +1 опора в стартовой вершине (две в одной точке). Это первое, что вылезет при сверке.
Длина лаг: дефолт режима не VBA-шный. VBA добавляет к gridleng линии и внешнего контура, и проёмов, параллельные лагам (после дедупа с сеткой, b2_mains:140-213). В порте *opor-boundary-lag-length-mode* = "holes" — контурные линии не считаются (opor-config.lsp:81). VBA-эквивалент — "all". Флаг явно оставлен для тюнинга, но дефолт сейчас отличается.
Допуск узлы-vs-границы 1.0 вместо 0.01. VBA чистит узлы против границ через equalpointsDel2 с 0.01; в порте *opor-vba-node-border-tolerance* = 1.0 — узел в миллиметре от конца линии сетки будет съеден, у VBA — нет.
Var: нет подъёма отрицательных отметок. VBA при отрицательной минимальной отметке поднимает всё на zfloor (b2_mains:50-57) и потом восстанавливает CHPOL. В порте этого нет — на чертежах с отметками типа -0.150 высоты и диапазоны разойдутся.
Var: ITOG считает по-разному. VBA в var_heght_fin суммирует только опоры, чей цвет сматчился со строкой таблицы (ошибки цвета 30 не входят); порт пишет общее число блоков. Плюс QC/QR: порт жёстко "0", VBA — qplw/qpltrim (пусто в режиме доски).
Округление. VBA Round — банковское (0.5 → чётное), и высоты вершин треугольников идут через CLng, а lev = hmax − Round(z). Порт округляет арифметически и разницу целиком. На полуцелых высотах возможен сдвиг на 1 мм → соседний диапазон → другой цвет.
Динамическая видимость таблицы не выставляется. VBA после вставки table_totl_* вызывает dyn_blkset («Доска»/«Плитка»); s_dyn_blk не перенесён — блок вставится в дефолтном состоянии видимости.
Числовые атрибуты 1..40 затираются пустыми. VBA пишет только сматченные тэги, остальные не трогает (остаются дефолты шаблона); порт перезаписывает всё.
Границы высотных областей упрощены. У VBA для концов линий сетки отдельный getH_bords (интерполяция вдоль граничных линий областей, точки «не на границе» перекидываются в узлы, отдельное сообщение об ошибке). Порт всё гонит через триангуляцию — численно близко (край треугольника = та же линейная интерполяция), но краевые случаи разойдутся. README это честно признаёт.
Один контур за запуск. VBA крутит цикл контуров с накоплением qop/gridleng/areatotl и одной таблицей в конце; порт — один контур = одна таблица. Для S1 не важно, для реальных проектов — важно.
Мелочи: нет проверок самопересечения контура (chk_reg), предложения замкнуть полилинию, «начальная точка внутри контура», «отметка пола > max отметки»; контурные лаги в порте фильтруются по длине >10, в VBA — нет; opor-grid-build-family — мёртвый код.
