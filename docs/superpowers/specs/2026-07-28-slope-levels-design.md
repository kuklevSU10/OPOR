# Автоматические отметки по областям уклона

## Назначение

Команда `OPORSLOPELEVELS` решает обратную задачу существующей команды `%`:
по одной известной высотной отметке и заданным блокам `slope` рассчитывает
отметки всех вершин разуклонки.

TIN образует прямую сторону этой же модели: по трём известным отметкам каждого
треугольника вычисляется градиент плоскости и автоматически вставляется один
блок `slope` в центр. Стрелка направлена от меньшей высоты к большей. Точный
процент и компоненты градиента сохраняются в служебной XData, видимая подпись
округляется до 0,001%.

## Входные данные

- внешний контур объекта;
- замкнутые полилинии областей на слое `линии_высот`;
- ровно один блок `slope` с неотрицательным процентом строго внутри каждой
  области; `0%` означает корректную горизонтальную поверхность;
- одна числовая базовая отметка `otmetka_oporvb`, стоящая в вершине области.

Стрелка `slope` считается направленной от меньшей высоты к большей. Поворот и
динамическое свойство `Угол` читаются тем же кодом, что использует проверенная
ручная команда `OPORWRITELEVEL`.

## Расчёт

Уникальные вершины с допуском 1 мм образуют узлы графа. Области связывают свои
вершины. От известного узла отметка распространяется внутри области по формуле:

`h2 = h1 + percent × signed_projection(P2 - P1) / 100`

Знаковая проекция берётся на направление повышения блока `slope`. Дробная
высота сохраняется на всех промежуточных переходах, а банковское округление до
миллиметра выполняется один раз при записи итоговой подписи. Поэтому ошибка не
накапливается вдоль цепочки треугольников.

Если вершина достигается несколькими путями, результаты сверяются. Расхождение
до 1 мм допускается; больше 1 мм считается конфликтом.

## Безопасность записи

До изменения отметок проверяется вся сеть. Запись не выполняется, если:

- область не содержит ровно один корректный блок `slope`;
- базовая отметка не стоит в вершине;
- есть несвязанные с базой области;
- найден конфликт больше 1 мм.

Проблемные вершины отмечаются оранжевыми кругами. При успешной проверке
существующие отметки обновляются, недостающие вставляются с XData `OPOR`.

## Интерфейс первой версии

Прямая команда: `OPORSLOPELEVELS`. Командный fallback `OPOR` также содержит
режим `SlopeLevels`. Добавление отдельной кнопки в CP1251-файл `opor.dcl`
оставлено до живой приёмки, чтобы не менять проверенную DCL-панель до проверки
семантики стрелки на реальном DWG.

## Проверка

Pure Core smoke должен подтверждать:

- две связанные области дают полный набор отметок без конфликтов;
- несовместимые направления/проценты дают конфликт;
- отдельная область остаётся неразрешённой.

После этого обязателен live-прогон в обычном AutoCAD на реальном примере
разуклонки с визуальной проверкой направления стрелок и подписей отметок.
