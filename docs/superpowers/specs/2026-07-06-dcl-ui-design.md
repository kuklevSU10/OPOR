# DCL-панель для OPOR (v3.6-dcl-ui) — дизайн

Дата: 2026-07-06. Статус: одобрен пользователем (макет v2 «ближе к оригиналу»).

## Зачем

Порт вводит всё командной строкой; в VBA-оригинале были формы (ufrm_mode /
ufrm_steps / ufrm_H) + мелкие удобства. Возвращаем панель средствами чистого
AutoLISP — **DCL** (ноль доустановок, главное требование проекта). OpenDCL и
HTML-палитры отвергнуты: требуют установки runtime / хрупкие.

## Состав UI

**Диалог 1 «OPOR» (меню, по образцу sayan-формы):** сетка кнопок 3×3 —
A (пост. высота), B (перем. высота), Slope, %, h⇕, Ring, +0.000, Очистка,
? (проверка чертежа = OPORCHECK); внизу «Отмена»; шапка: «sayan group» текстом
+ «Ver <*opor-version*>»; футер: project@sayangroup.ru / тел. +7 495 136 6050.
Непортированные кнопки (Slope, %, h⇕, Ring, +0.000) — задизейблены
(`mode_tile`), оживут по мере портирования вспом. инструментов.

**Диалог 2 «Ввод» (параметры, layout оригинала ufrm_steps):**
- группа «Шаги»: вдоль вектора / вдоль перпендикуляра (edit_box);
- группа «Общая длина»: radio вдоль вектора / перпендикуляра (= lag-axis);
- «Отметка чистого пола», «Радиус обозначения опоры» (edit_box);
- группа «Покрытие»: radio Доска/Плитка; толщина доски, толщина лага,
  толщина плитки; «шаг доп. лаг» — ЗАДИЗЕЙБЛЕН до П9 (сдвоенные лаги);
- группа «Линейка»: radio Level / Level 3D / Level PRO;
- группа «Крепёж» (ТЗ п.4 — заказчик сам просил в форму ввода): popup лаги
  [Нет/Level TOP/Level Clip], popup плитки [Нет/Lastra/Tile/Tile Soft/
  Lastra Soft], edit «шаг креплений» (активен при плитке ≠ Нет); суффикс
  « 3D» добавляется автоматически по линейке;
- toggles: «показать разбивку» (Var), «скрыть лишние слои»;
- OK / Отмена + errtile для сообщений валидации.

Режимные состояния: в Const неактивны отметка пола, покрытие, толщины,
«показать разбивку»; в Var — всё активно, покрытие Доска включает толщины
доски/лаги, Плитка — толщину плитки.

**Диалог 3 «Опора» (только Const, аналог ufrm_H):** list_box строк
«N. имя  диапазон  цвет C» из таблицы «Опоры» по выбранной линейке; OK/Отмена.

## Поток

`OPOR` → меню → контур/проёмы мышью (как сейчас) → «Ввод» → (Const) «Опора» →
клики точек (начало/направление/таблица) → построение. Var: проверка отметок
до формы (как сейчас); проверка «пол выше max отметки» — после OK: alert и
форма открывается заново с введёнными значениями (цикл).

## Удобства (перенос из VBA, починенные)

1. **«показать разбивку»** (chkbox_tri→istriang): в Var рисуются замкнутые
   LWPolyline треугольников триангуляции на слое **«линии_высот3»** (создать,
   если нет — VBA падал на «0»), каждый регистрируется XData → OPORCLEAN убирает.
2. **«скрыть лишние слои»** (замена мёртвого uv_hide_lays, в VBA не вызывался и
   был сломан): после OK формы гасятся (LayerOn=nil) все слои, кроме белого
   списка (контур, сеткаvb, плиткаvb, областиvb, опорыvb, опоры_текстvb,
   линии_высот, линии_высот3, текущий слой); исходные состояния запоминаются и
   **гарантированно восстанавливаются** в конце прогона и на путях
   отмены/ошибки.
3. **Возврат вида** (аналог SetView "vb_original" в b3_fin): в начале прогона
   запоминаются VIEWCTR/VIEWSIZE, в конце успешного прогона вид возвращается
   ZoomWindow-ом. Без галки, всегда.

## Архитектура

- **`OPOR/opor.dcl`** — 3 диалога. Кодировка **CP1251** (DCL не понимает UTF-8;
  файл создаётся/правится только питоном с encoding='cp1251', НЕ инструментом
  Write). Ищется через `findfile "opor.dcl"`.
- **`OPOR/opor-dcl.lsp`** — новый модуль: показ диалогов, колбэки
  (action_tile/mode_tile/set_tile), валидация чисел, память формы
  `*opor-form-memory*` (alist, живёт сессию AutoCAD, как VBA arrfrm),
  функции удобств (слои, вид, число-парсер).
- **`opor-ui.lsp`** — ветвление: `(if (opor-dcl-ready-p) <DCL-путь> <старый>)`
  в select-mode / read-params / read-var-params. Старый командный код
  НЕ трогается. Результат DCL кладётся в те же session-ключи.
- **`opor-config.lsp`** — `*opor-use-dcl*` T (nil = принудительно командная
  строка), белый список слоёв `*opor-visible-layers*`, версия `3.6-dcl-ui`.
- **`opor-levels.lsp`** — отрисовка треугольников по флагу сессии
  'show-triangles.
- **`opor-core.lsp`** — вызовы вид-сейв/рестор и слои-рестор в финалах и на
  путях отказа; `opor-loader.lsp` — загрузка opor-dcl.lsp.

`opor-dcl-ready-p` = `*opor-use-dcl*` ∧ findfile ∧ load_dialog успешен; любое
падение DCL → лог + автоматический фолбэк на командный ввод.

## ВАЖНО: сверка и логи

Ввод в DCL-форме НЕ пишется в лог AutoCAD. Перегон эталонов — только с
`(setq *opor-use-dcl* nil)` (командный ввод, логируемый). Дописать в
`эталоны/README.md`.

## Не входит (YAGNI)

Поле «шаг доп. лаг» активным (П9), кнопки 7 вспом. инструментов рабочими,
логотип-картинка (.sld), сохранение памяти формы в реестр.

## Проверка

1. verify_opor.py (статически) после каждой правки.
2. AutoCAD смоук: Const через форму на геометрии S1/S3 — числа те же, что в
   эталоне (форма = только способ ввода); Var через форму; Отмена в каждом
   из 3 диалогов (ничего не создано, слои/вид не тронуты); «скрыть лишние
   слои» — слои вернулись; «показать разбивку» — треугольники есть и
   OPORCLEAN их убирает; `(setq *opor-use-dcl* nil)` — старый ввод работает.
