# П5 «Сетка строго вдоль лаг» — дизайн (v3.5-tz-p5-lag-grid)

Дата: 2026-07-06. Статус: одобрен пользователем (устно в сессии).

## Контекст

ТЗ Дмитрия, заголовок «Добавление раскладки лаги»:

> Расчёт, проводимый на лагу, необходимо исправить. Сам плагин выстраивает сетку,
> по которой считается длина лаг, необходимо, чтобы эта сетка выстраивалась
> исключительно вдоль лаг (убрать из расчёта построение сетки по раскладке или
> размеру плитки).

Факты, установленные при анализе:

- Расчёт LENGTH и в VBA (`trimXL`: `If arrgrid(3, qgr) = arrfrm(9)`), и в порте
  (`grid-length` = только `lag-lines`) уже идёт исключительно по лаговому семейству
  + рёбрам контура/проёмов, параллельным лагам. Числового бага в порте нет.
- Но в чертёж рисуются ОБА семейства линий (S1: 9 лаг + 6 поперечных + 1 ребро =
  16 линий / 60000 мм на `сеткаvb` при LENGTH=30 м).
- Жалоба ТЗ порождена VBA-режимом «плитка» (`copXLines`: размер плитки = шаг сетки);
  в порте плитка не портирована — правило фиксируется на будущее (П8).
- Новый визуал таблицы (присланный dwg) содержит колонку «Кол-во лаг, шт» — при
  нарисованных поперечных линиях её не посчитать.

Решение пользователя: **в чертеже остаются только лаги** (вариант «А: строить и
удалять» — поперечные строятся временно тем же кодом, затем физически удаляются).

## Что меняется для пользователя

- После прогона `OPOR` (Const и Var) на `сеткаvb` остаются только линии вдоль лаг:
  лаговое семейство + рёбра контура/проёмов, параллельные лагам (`grid-edge`).
- Опоры (количество, позиции, цвета), LENGTH, AREA, итоговая таблица — без изменений.
- В финальном логе и `OPORDUMP` появляется «лаг N шт» (число рядов).
- Инвариант для сверки: сумма длин линий на `сеткаvb` = LENGTH × 1000 (мм), ровно.

## Реализация

1. **`opor-config.lsp`**
   - `*opor-keep-perp-grid*` — default `nil`. `T` = старое поведение (обе семьи
     линий остаются, как VBA) — для A/B-сверок со старым плагином.
   - `*opor-version*` → `"3.5-tz-p5-lag-grid"`.

2. **`opor-core.lsp`** — хелпер `opor-unregister-created obj`: убрать объект из
   session-списка `created-objects` (парный к `opor-register-created`).

3. **`opor-grid.lsp`**, конец `opor-grid-build` — после снятия `node-points` /
   `endpoint-points` в списки точек:
   - если `*opor-keep-perp-grid*` = nil: физически удалить поперечное семейство
     (при `lag-axis="vect"` — p-lines, при `"perp"` — v-lines) через
     `opor-delete-object` + `opor-unregister-created`;
   - в grid-структуре поперечный список заменить на `'()`;
   - `(opor-session-set 'perp-lines-removed N)`;
   - подсчёт лаг: `'lag-row-count` = число групп коллинеарных отрезков
     (lag-lines + созданные grid-edge) по смещению поперёк лаг, допуск 1 мм.
     Отрезки одного ряда (разрезанные проёмом) = одна лага. S1 → 10.

4. **`opor-core.lsp`** — в финальные строки лога Const и Var добавить
   «, лаг=N шт»; **`opor-dump.lsp`** — в сессионный блок OPORDUMP вывести
   `lag-row-count` и `perp-lines-removed` (grid-p станет 0 естественно, код
   классификации не трогать).

5. **`эталоны/README.md`** — после перегона обновить числа слоя `сеткаvb`
   (S1: 16/60000 → 10/30000; S2/S3/S5 — снять фактические), пометить
   «после П5 v3.5»; числа опор и таблиц не меняются. Зафиксировать инвариант
   `сеткаvb = LENGTH×1000`.

## Что НЕ входит

- Запись «Кол-во лаг» в таблицу — ждёт П3 (новый визуал). Перед записью уточнить
  у Дмитрия трактовку «Кол-во лаг, шт»: ряды (наша) vs закупочные штуки
  (длина ÷ длина доски).
- Режим «плитка» (П8), сдвоенные лаги (П9) — отдельные пункты; плиточная сетка
  будет строиться отдельным этапом, лаговая остаётся как здесь.

## Риски и краевые случаи

- Удаление идёт ПОСЛЕ снятия точек — расстановка опор бит-в-бит прежним кодом.
- Var-режим использует тот же `opor-grid-build` — поведение одинаковое; уровни
  (getH_*) работают по точкам/контурам, линии сетки им не нужны (проверено grep).
- Удалённые объекты вычищаются из реестра — `OPORCLEAN Session` и `OPORDUMP`
  не встречают мёртвых VLA-объектов (в `opor-clean-session` и так есть guard).
- `lag-axis` nil → трактуется как "vect" (существующий дефолт).
