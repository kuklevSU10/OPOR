## Как перегонять

0. **С v3.6:** `(setq *opor-use-dcl* nil)` — иначе ввод пойдёт через DCL-панель и
   НЕ запишется в лог. После перегона вернуть: `(setq *opor-use-dcl* T)`.
   **С v3.8** в командном вводе есть вопрос «Шаг сдвоенных лаг» (Enter=0),
   **с v3.9** — вопрос «Покрытие [d/p]» и в Const (Enter=d), причём покрытие
   спрашивается ДО сдвоенных лаг (при «p» вопрос о сдвоенных лагах пропускается).
1. Взять `*_lisp.dwg` нужного сценария → `OPORCLEAN` → `All` (получается чистый исходник).
2. `APPLOAD` `OPOR/opor-loader.lsp` → `OPOR` → режим и вводы из карточки ниже.
3. `DUMPALL` (из `check_dump.lsp`) + `OPORDUMP` + `OPORTABLES`.
4. Сверить с числами ниже. Любое расхождение целых = регрессия.
5. Логи пишутся автоматически (LOGFILEMODE=1), эталонные копии — в `логи/`.

Общий ввод: контур кликом, нач. точка `0,0`, направление `@1<0`, таблица `7000,3000`.
Геометрия S1: прямоугольник 3000×5000 в 0,0 на слое «контур».

## Известные задокументированные отклонения порта

1. Границы областей высот: ближайшая линия vs «первая найденная» у VBA.
2. Ошибочные опоры: цвет 30 + атрибут «?» (VBA деградирует в пусто/цвет 0).
3. Дробные высоты в атрибутах: точка вместо запятой.
4. Слой блока итоговой таблицы: текущий слой на момент прогона (у VBA так же).
5. S4: VBA-баг «регионов-двойников» НЕ воспроизводим (решение Б): у VBA
   нетронутая плитка возле проёма может задвоиться регионом; у порта в ветке
   «плитка не изменилась» временный регион удаляется.
6. S4: QC/QR порт считает по объектам своей сессии, VBA — по слою «плиткаvb»
   в bbox (цепляет старые плитки прошлых прогонов). На чистом чертеже числа
   совпадают бит-в-бит.
7. ETS7/Slope: VBA не видит блок `<2%` после переноса на выключенный
   `опоры_текстvb` и не удаляет соответствующие опоры. Порт намеренно видит
   скрытый блок и выполняет исходную ветку удаления; решение пользователя:
   «баг не нужен».
