# Автоматическая установка OPOR

Эта папка содержит исходники однокнопочного установщика для чистовой выдачи:

- `INSTALL_OPOR.cmd` — файл, который запускает заказчик;
- `install_opor.ps1` — проверка, резервное копирование и установка;
- `COLLECT_OPOR_LOGS.cmd` и `collect_opor_logs.ps1` — сбор диагностических
  журналов в ZIP на рабочем столе;
- `autoload/PackageContents.xml` — описание штатного Autodesk `.bundle`;
- `autoload/OPOR_bootstrap.lsp` — автоматическая загрузка модулей OPOR.

При сборке релиза CMD и короткая инструкция остаются в корне выдачи, а скрипт,
`autoload/`, `OPOR/` и ручной launcher складываются в `_OPOR_FILES/`. Заказчик
видит две очевидные кнопки: установить OPOR или собрать диагностические логи.

Установщик ставит bundle только в архитектурно-нейтральные папки, которые
AutoCAD 2023 (64-бит) реально сканирует, — без неоднозначности
`Program Files` / `Program Files (x86)`:

- обычный двойной клик → per-user `%APPDATA%\Autodesk\ApplicationPlugins`
  (права администратора не нужны);
- «Запуск от имени администратора» → all-users
  `%PROGRAMDATA%\Autodesk\ApplicationPlugins` для всех учётных записей ПК.

В любом режиме остаётся ровно одна живая копия: старые `OPOR.bundle` во всех
штатных корнях (включая ошибочный x86 из прежних версий) переносятся в резервные
`OPOR.bundle.backup-ДАТА-ВРЕМЯ`. Bundle-версия поднята до 3.32.0, поэтому новая
копия перекрывает любую застрявшую старую.

Номер версии живёт ровно в одном месте — `AppVersion` в
`autoload/PackageContents.xml`. Установщик и bootstrap его читают, а не хранят
у себя: раньше зашитые строки разъезжались с реальной сборкой.

На компьютере пользователя журналы установки, автозагрузки и работы команд
складываются в `%LOCALAPPDATA%\OPOR\logs`. В AutoCAD папку можно открыть командой
`OPORLOGS`.
