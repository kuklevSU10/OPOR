# S6 «Сдвоенные лаги» — дизайн порта 1:1 (v3.8-s6-dbl-lags)

Дата: 2026-07-07. Статус: одобрен пользователем (устно в сессии).

## Контекст

Этап: пользователь решил СНАЧАЛА закончить перенос всего функционала VBA, ТЗ — после.
Порядок переноса: **сдвоенные лаги → плитка → 7 вспом. инструментов → chk_reg →
мультиконтур**. Этот документ — первый кусок: сдвоенные лаги, строго 1:1 с VBA.

Механика VBA (установлено по исходникам):

- `ufrm_steps.tbox_2lag` → `arrfrm(11)` — **шаг доп. лаг в мм** (целое, 0 = выкл).
  Режим «плитка» принудительно пишет `arrfrm(11) = "0"`.
- `a1_mains` (после основных семейств, до extrim): если `arrfrm(11) <> 0`,
  `copyxlinlag` копирует XLine **лаговой** ориентации (`arrfrm(9)="perp"` → xlinperp,
  иначе xlin) с шагом `arrfrm(11)` в ОБЕ стороны от базовой точки; `q` начинается
  с 1 — на нулевой позиции доп. лаги нет; копии останавливаются, когда линия
  перестаёт пересекать bbox-полилинию. Цвет копий **12**.
- `trimXL` после обрезки: линии цвета 12 помечаются суффиксом `#` («vect#»/«perp#»);
  затем дедуп: если у двух линий совпали начала И концы (допуск **10 мм** покоорд.),
  удаляется та, что с `#` (доп. лага), основная остаётся. После дедупа `#`
  стирается — доп. лаги дальше неотличимы от основных: опоры на них ставятся
  (вершины/границы/узлы), в LENGTH входят.
- **Квирк LENGTH (решение пользователя: воспроизводить 1:1):** сумма длин
  (`grlengCur`) в `trimXL` считается ДО дедупа. Совпавшая с сеткой доп. лага
  удаляется с чертежа, но её длина остаётся в LENGTH. При шаге доп. лаг, кратном
  шагу сетки, чертёж идентичен прогону без доп. лаг, а LENGTH раздут. Инвариант
  П5 «длина линий сеткаvb = LENGTH×1000» при включённых доп. лагах НЕ держится.
  Чинить — на этапе ТЗ (кандидат в вопросы Дмитрию).

## Что меняется для пользователя

- В форме «Ввод» оживает поле «Шаг сдв. лаг» (0 = выкл, по умолчанию 0, значение
  помнится в памяти формы на сессию). В командном фолбэке (`*opor-use-dcl* nil`)
  появляется вопрос `Шаг сдвоенных лаг <0>:` — попадает в лог (важно для эталонов).
- При шаге > 0 на `сеткаvb` появляются доп. лаги **цвета 12** параллельно основным;
  на них ставятся опоры; LENGTH и таблица считаются по правилам VBA (с квирком).
- Работает и в Const, и в Var (сетка общая).
- `OPORCLEAN` их чистит, `OPORDUMP` показывает: создано/удалено дедупом.
- В счётчик П5 «лаг=N шт» выжившие доп. лаги входят как отдельные ряды.

## Реализация

1. **`opor-config.lsp`**: `*opor-version*` → `"3.8-s6-dbl-lags"`;
   `*opor-vba-dbl-lag-dedupe-tolerance*` = 10.0 (мм, maxDst в trimXL);
   `*opor-dbl-lag-color*` = 12. Дефолт уже есть: `double-lag-step` = 0.0
   в `*opor-default-params*` — это имя параметра сессии везде далее.

2. **UI**:
   - `opor-dcl.lsp`: поле `dbllag` включить (`mode_tile` 0 в обоих режимах);
     `set_tile` из памяти формы (`'double-lag-step`, дефолт 0); чтение при OK:
     неотрицательное число, иначе errtile (как остальные поля). Записать в
     параметры сессии.
   - `opor-ui.lsp` (командный фолбэк `opor-ui-*-cmd`): вопрос
     `Шаг сдвоенных лаг <0>:` (getreal с дефолтом 0, отрицательное → переспрос)
     рядом с вопросами шагов/радиуса — и в Const-, и в Var-ветке.
   - На будущее (порт плитки): режим «плитка» форсит `dbl-lag-step` = 0, как VBA.

3. **`opor-lags.lsp`** (сейчас заглушка — модульная граница проекта):
   - `opor-dbl-lag-raw-lines session vec perp bbox` — построить raw-семейство
     параллельно лагам: ось = лаговая ось, шаг = `dbl-lag-step`, индексы из
     `opor-index-range-for-bbox`, **исключая индекс 0** (VBA q≥1); тем же
     `opor-grid-build-family-range`-механизмом, xtype `"grid-dbl-raw"`.
   - `opor-dbl-lag-apply session boundary holes lag-lines` — полный цикл:
     raw → `opor-trim-lines-by-boundaries` (xtype `"grid-dbl"`) →
     `opor-filter-short-grid-lines` → покрасить в цвет 12 → посчитать сумму длин
     ВСЕХ выживших обрезков (это слагаемое LENGTH — до дедупа) → дедуп против
     lag-lines: оба конца в допуске 10 мм (сравнение как в VBA: старт-к-старту,
     конец-к-концу, без разворота — ориентация у порта детерминирована) →
     совпавшие удалить физически + `opor-unregister-created`.
     Вернуть `(surviving-lines . length-mm-до-дедупа)` + положить в сессию
     `'dbl-lag-created N`, `'dbl-lag-deduped M`.

4. **`opor-grid.lsp`** (`opor-grid-build`), после определения `lag-lines` и
   `grid-length`:
   - если `dbl-lag-step` > 0: вызвать `opor-dbl-lag-apply`;
     `grid-length` += длина-до-дедупа (квирк);
     выжившие доп. лаги **добавить в лаговое семейство** (`v-lines`/`p-lines`
     по `lag-axis` и в `lag-lines`) ДО: расчёта рёбер контура/проёмов
     (`opor-boundary-lag-segments` — чтобы ребро не легло поверх доп. лаги),
     `node-points`, `endpoint-points`, `lag-row-count`.
   - Доп. лаги параллельны лагам → П5-удаление поперечных их не касается.

5. **`opor-dump.lsp`**: в OPORDUMP строка «S6 сдв. лаги: шаг=…, создано=…,
   дедуп=…» (при шаге 0 — не выводить). Классификация xtype `"grid-dbl"` в
   существующий разбор.

6. **`эталоны/README.md`**: новая карточка S6 (два прогона, числа после сверки).

## Что НЕ входит (этап ТЗ, п.9 — после переноса)

- Раскладка «ровно» / «со сдвигом ½ доски», шахматный порядок опор соседних рядов.
- Честный LENGTH (без квирка) и трактовка «Кол-во лаг, шт» для таблицы.
- Взаимодействие с режимом «плитка» (плитка ещё не портирована).

## Риски и краевые случаи

- Дедуп точек опор (1 мм, v3.7) сам схлопнет узлы, где доп. лага прошла почти по
  основной, но пережила 10-мм дедуп линий, — расхождения с VBA тут возможны только
  в экзотике (VBA в этом случае ставит два блока друг на друга; наша защита от
  наложения — осознанное отклонение v3.7, уже задокументировано).
- `opor-index-range-for-bbox` даёт диапазон по bbox, VBA останавливается по первому
  непересечению bbox-полилинии — множества позиций совпадают (монотонность).
- Память формы хранит шаг на сессию AutoCAD — как все поля формы (VBA хранит в
  `arrfrm` так же).
- Шаг ≥ размера bbox → диапазон индексов пуст (кроме 0, который исключён) →
  доп. лаг нет, поведение = выкл; VBA аналогично (первая копия вне bbox удаляется).
