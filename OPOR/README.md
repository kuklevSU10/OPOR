# OPOR 3.31 LISP Port

Чистый AutoLISP / Visual LISP порт плагина `opor` без `.dvb`, `vl-vbarun`,
`USERS4/USERS5`, Express Tools и `geomcal`.

Актуальный живой статус проекта находится в `../HANDOFF.md`.

## Загрузка

В AutoCAD:

1. `APPLOAD`
2. выбрать `OPOR/opor-loader.lsp`
3. запустить `OPOR` или старый алиас `XX`

Команды:

- `OPOR` - главное меню DCL: Const / Var / Slope / % / `h` / Ring /
  `+0.000` / TIN / Clean / `?`.
- `XX` - алиас для совместимости со старым запуском.
- `OPORSLOPEWR` - рассчитать и записать проценты в блоки `slope`.
- `OPORSLOPE` - перекрасить/удалить опоры и вставить `table_slope`.
- `OPORHEIGHTCHECK` - проверка одной опоры (`?` в форме).
- `OPORWRITELEVEL` - пересчёт выбранных отметок (`h` в форме).
- `OPORAUTOLEVEL` - расстановка пустых отметок (`+0.000` в форме).
- `OPORSLOPELEVELS` - автоматический расчёт отметок по общей базовой отметке,
  замкнутым областям `линии_высот` и блокам `slope` внутри них.
- `OPORGEOLEVELS` - импорт XYZ из proxy-точек `GEO_POINTS`: режим `Сетка`
  прореживает исходные отметки по заданному шагу, режим `Линии` интерполирует
  высоты в вершинах выбранных линий/полилиний. Команда пока вызывается напрямую,
  отдельной кнопки DCL нет.
- `OPORRING` - ведомость уже расставленных опор внутри выбранного контура.
- `OPORTIN` - построить треугольные области высот и поставить в каждом
  треугольнике рассчитанный блок `slope` со стрелкой снизу вверх.
- `OPORREGCHECK` - отдельная проверка полилинии через временный `Region`.
- `OPORCHECK` - проверка слоев и блоков текущего DWG/DWT.
- `OPORCLEAN` - очистка объектов, помеченных XData `OPOR`.
- `OPORDUMP` - диагностика новых объектов с XData `OPOR`.
- `OPORTABLES` - атрибуты итоговых блоков `table_totl_*`.
- `OPOROLD` - снимок старых VBA-объектов внутри контура текущей сессии.
- `OPORSHOW` - приблизить объект по handle из диагностического вывода.
- `OPORDEBUG` - печать текущей session-структуры.

## Модули

Порядок загрузки задает `opor-loader.lsp`:

- `opor-config.lsp` - версия, константы, настройки совместимости.
- `opor-errors.lsp` - обработчики ошибок и безопасное восстановление.
- `opor-geometry.lsp` - геометрия, полилинии, площади, проемы, zoom.
- `opor-cleanup.lsp` - XData и очистка объектов порта.
- `opor-dump.lsp` - диагностика `OPORDUMP`/`OPOROLD`.
- `opor-tables.lsp` - чтение и запись итоговых таблиц.
- `opor-ui.lsp` - командный ввод и UX-обвязка выбора.
- `opor-dcl.lsp` - DCL-панель и сбор параметров из формы.
- `opor-trim.lsp` - обрезка линий по контуру.
- `opor-grid.lsp` - сетка, лаги, П5 "сетка вдоль лаг".
- `opor-supports.lsp` - расстановка опор.
- `opor-levels.lsp` - переменные высоты, области, триангуляция.
- `opor-tiles.lsp` - S4 плитка (ковёр, Boolean-регионы, QC/QR).
- `opor-lags.lsp` - S6 сдвоенные лаги (copxlinlag + дедуп из trimXL).
- `opor-slope.lsp` - связка `%`/`Slope`, цвета и таблица корректоров.
- `opor-height-check.lsp` - проверка высоты одной опоры (`?`).
- `opor-write-level.lsp` - пересчёт отметок от воронки и блока уклона (`h`).
- `opor-auto-level.lsp` - пустые отметки в уникальных вершинах областей (`+0.000`).
- `opor-geo-levels.lsp` - безопасное чтение proxy-геосетки и создание отметок
  `otmetka_oporvb` (`OPORGEOLEVELS`).
- `opor-ring.lsp` - сокращённая итоговая таблица по существующим опорам (`Ring`).
- `opor-tin.lsp` - автоматическая триангуляция Делоне по отметкам (`TIN`).
- `opor-core.lsp` - основной сценарий Const/Var.

## Реализовано

- Golden-master паритет с VBA для S1/S2/S3/S5 и Сириуса.
- Постоянная высота: контур, автопроемы, сетка, обрезка, опоры, таблица.
- Переменная высота: проверки отметок, области высот, интерполяция, триангуляция,
  таблица и диагностика ошибок.
- DCL-панель по образцу VBA-формы.
- По актуальной линейке заказчика пользовательский выбор содержит только
  `Level 3D` и `Level PRO`; обычный `Level/lev` скрыт, дефолт — 3D.
- UX-pass v3.7: автоскрытие лишних слоев, автопроемы, зум на контур, подсветка
  контура, переспрос при промахе точки, Enter-дефолты, безопасный Esc.
- ТЗ: П10 площадь минус `областиvb`, П4 каркас крепежа, П5 сетка строго вдоль лаг.
- S6 сдвоенные лаги v3.8: доп. семейство параллельно лагам (шаг из формы/вопроса,
  0 = выкл), цвет 12, дедуп совпавших с сеткой (допуск 10 мм); LENGTH считается
  ДО дедупа — квирк VBA воспроизведён 1:1 (инвариант «сеткаvb = LENGTH×1000» при
  включённых сдвоенных лагах не действует).
- S4 плитка v3.9: покрытие [d/p] выбирается в Const и Var; ковёр плиток на
  `плиткаvb` (целые — полилинии, обрезанные контуром/проёмами — регионы через
  `vla-Boolean`), QC/QR в таблице = целых/обрезанных. Отклонения от VBA: без
  регионов-двойников у нетронутых плиток возле проёмов (баг VBA), счёт по
  объектам сессии, а не по слою.
- SLOPE v3.10: `%` рассчитывает 1%…N% по отметкам областей; `Slope`
  мультиконтурно красит P2…P9, удаляет опоры `<2%` и заполняет `table_slope`.
  ETS7 принят 2026-07-14. Runtime-баг VBA, не удаляющий `<2%` из-за выключенного
  слоя, намеренно не воспроизводится по решению пользователя. Утверждённый
  клиентский визуал `table_slope` включён в `opor-table-blocks.dwg`: если блока
  нет в текущем DWG, `Slope` дозагружает его автоматически; существующее
  определение не переопределяется.
- Проверка высоты v3.11: кнопка `?`, четыре диагностических блока; ETS8 LISP/VBA
  совпали бит-в-бит.
- `h` / write_levl v3.12: VBA-цепочка XLine/IntersectWith, компенсация
  межъязыкового COM-шума перед Round, сохранение префикса `+`; ETS9 LISP/VBA
  совпали бит-в-бит.
- `+0.000` / auto_levl v3.13: crossing-области по bbox, дедуп вершин `<1` мм,
  вставка пустых `otmetka_oporvb`; ETS10 LISP/VBA совпали бит-в-бит.
- `Ring` / m_ring v3.14: поиск существующих опор по bbox контура, совпадение
  цвета и верхних 10 мм диапазона, вставка `table_totl_*`; ETS11 LISP/VBA
  совпал по 9 входным блокам, `table_totl_1`, `ITOG=6` и атрибутам.
- `chk_reg` v3.15: внешний контур и все автоматически найденные проёмы
  проверяются созданием временного `Region`; самопересечение останавливает
  расчёт до формы параметров. ETS12 LISP/VBA принят: оба отвергли плохой
  внешний контур и плохой проём, не оставив Region/сетки/опор/таблицы.
- Мультиконтурный цикл v3.16: Const/Var принимают следующие контуры до Enter,
  повторно спрашивают только старт и направление сетки, суммируют площадь,
  опоры, лаги, плитку, крепёж и ошибки высот; итоговая таблица вставляется одна.
  Сырые миллиметры лаг округляются только после суммирования всех контуров.
- Авто-TIN v3.17: отдельный препроцессор строит по отметкам замкнутые
  треугольники на `линии_высот`, фильтрует внешний контур и проёмы, маркирует
  результат XData `OPOR` и безопасно заменяет только прежние авто-треугольники.
  ETS15 принят: авто и ручной путь совпали по четырём треугольникам и точному
  распределению высот всех 61 опоры.
- Constrained TIN v3.18: после обычного Делоне восстанавливаются рёбра внешнего
  контура и проёмов переворотами внутренних рёбер; это закрывает клин без
  покрытия у вогнутых границ.
- TIN v3.30: отметки вершин внешнего контура остаются обязательными, а
  отсутствующие высоты вершин внутренних проёмов вычисляются по предварительной
  поверхности и сохраняются служебными блоками для последующего запуска `B`.
- TIN v3.30.1: восстановление длинных рёбер вогнутого контура использует очередь
  промежуточных переворотов и не останавливается, если первый новый диагональный
  edge пока ещё пересекает восстанавливаемое ребро.
- TIN-разуклонка: по трём отметкам каждого треугольника вычисляется градиент
  плоскости, в центр автоматически вставляется `slope`, а стрелка ориентируется
  от меньшей высоты к большей. Подпись показывает процент с точностью до 0,001,
  неокруглённые компоненты градиента сохраняются в XData `OPOR_TIN_SLOPE`;
  повторный TIN заменяет только прежние автоматические блоки `tin-slope`.
- Обратный расчёт `OPORSLOPELEVELS` держит дробные высоты на всей связной сети
  и округляет только итоговые подписи отметок. Уклон `0%` считается корректной
  плоской областью; для неизменённого авто-TIN используется точный процент из
  XData, а после ручного изменения атрибута главным становится видимое значение.
- Геоотметки `OPORGEOLEVELS`: выбранные `ACAD_PROXY_ENTITY` сначала копируются
  с нулевым смещением, раскрываются только временные копии, XYZ читается из
  полученных окружностей, затем вся временная геометрия удаляется. Исходные
  proxy остаются неизменными. Повторный запуск заменяет только прежние
  `geo-level-mark`, ручные отметки не перезаписывает. Совпадающие XY с заметно
  разными Z пропускаются как неоднозначные; для плотной сетки это оставляет
  безопасный локальный пробел. В метровых геодезических DWG масштаб нового
  блока автоматически принимается `0,001`, в обычных миллиметровых — `1`.
- Состав пола v3.31: TOP/CLIP работают с лагой, TILE — с плиткой на лаге,
  LASTRA — с плиткой напрямую на опорах. Каждый выбранный крепёж уменьшает
  расчётную высоту опоры на 4 мм; нижняя таблица автоматически меняет набор и
  порядок строк.
- Чистовые таблицы Level 3D/PRO: `opor-table-blocks.dwg` поставляет
  обе спецификации и общие `OPOR_PARAMS_TILE`/`OPOR_PARAMS_BOARD`.
  С v3.24 под нижнюю таблицу всегда добавляется число фактических рядов лаг;
  строки крепежа добавляются только для выбранных позиций.
- Автозаголовок v3.25: один `Разбивка опор Level 3D/PRO` ставится
  по центру над общим bbox всех контуров; ISOCPEUR, XData OPOR.
- Размерный стиль v3.26: при проверке среды `ISO-25` создаётся/обновляется
  по настройкам ТЗ; чужой активный стиль не переключается.
- П8 v3.27: шаги опор и размеры плитки вводятся отдельно. Опоры/лаги считаются
  по шагам опор, плиточный ковёр — по собственным размерам; TILE-таблица
  показывает оба независимых значения.
- П9 v3.28: для доски вводятся длина и схема `Нет / Ровно / Сдвиг 1/2`.
  На стыках создаются физические пары лаг; опоры второй лаги сдвигаются на
  половину шага. Старый ручной S6-путь сохранён для совместимости эталонов.
- П2 v3.29: старый цвет опор ACI 82 заменён на подтверждённый чистовой
  таблицей фиолетовый ACI 6; старые DWG-таблицы с 82 нормализуются при чтении.

## Проверка

Для логируемых эталонов можно отключить DCL:

```lisp
(setq *opor-use-dcl* nil)
```

Вернуть обычный режим:

```lisp
(setq *opor-use-dcl* T)
```

После правки:

1. Проверить статику `OPOR/*.lsp`.
2. Прогнать нужный DWG из `../эталоны/`.
3. Считать свежий `.log` как CP1251.
4. Сверить `DUMPALL`, `OPORDUMP`, `OPORTABLES` с `../эталоны/README.md`.
5. Обновить верхний раздел `../HANDOFF.md`.
