# S4 «Плитка» — дизайн порта (v3.9-s4-tiles)

Дата: 2026-07-07. Статус: одобрен пользователем (устно в сессии, «ебаш»).

## Контекст

Этап переноса VBA→LISP (после S6 сдвоенных лаг). Механика VBA (по исходникам
`a1_mains` / `copXLines` / `t_del_plitk` / `trimPlitks` / `trrimPlitkOpp`):

- Режим включается радио «плитка» в `ufrm_steps` (`arrfrm(4)="p"`); шаги
  `arrfrm(1)/(2)` играют роль размеров плитки (сетка при этом строится по тем
  же шагам — жалоба ТЗ п.8, чинится ПОЗЖЕ, сейчас 1:1). Дв. лаги форсятся 0.
- Построение: первая плитка — замкнутая полилиния-прямоугольник
  `CInt(шаг1)×CInt(шаг2)` от базовой точки, повёрнутая по направлению, слой
  `плиткаvb`; при копировании поперечных XLine создаётся ряд плиток вдоль
  вектора (позиция i·шаг1 вдоль vec), при копировании вдольных — весь ряд
  копируется на j·шаг2 вдоль perp. Итог: ковёр по bbox контура.
- `del_plitk`: плитка не пересекает контур и центр (середина диагонали) вне →
  удалить; внутри → «whole»; пересекает → «intersc».
- `trimplitk` (для intersc): регион контура ∩ регион плитки (Boolean COM);
  площадь <0.001 → плитка снаружи, удалить; площадь не уменьшилась (≤1 мм²) →
  касание, полилиния остаётся; уменьшилась → полилиния удаляется, обрезок
  живёт РЕГИОНОМ на `плиткаvb` (при распаде — несколько регионов через
  Explode; explode одного региона возвращает кривые — признак «не распался»).
  Регион контура создаётся заново для каждой плитки (Boolean мутирует его).
- `trimPlitkOpp` (по каждому проёму): плитки в bbox проёма: полилиния целиком
  внутри проёма → удалить; иначе регион плитки − регион проёма
  (acSubtraction): →0 удалить, уменьшилась → полилиния→регион, «не
  изменилась» → у VBA полилиния остаётся И созданный регион-двойник остаётся
  на слое — БАГ (дубль объекта, двойной счёт QC+QR).
- `calc_plitk`: по слою `плиткаvb` в bbox контура: полилинии → `qplw` (целые),
  регионы → `qpltrim` (обрезанные). В итоговую таблицу: **QC=qplw, QR=qpltrim**
  (оба режима; в режиме доски 0/0 — вот откуда наши «QC/QR="0"»).
- Опоры/сетка/LENGTH от плиток не зависят (слой выключается перед extrim).

## Решения пользователя

- Резка регионами через COM (`vla-AddRegion`/`vla-Boolean`) — 1:1 с VBA, дуги
  контура бесплатно.
- **Решение Б: баг дублирования НЕ воспроизводим.** Плитка-полилиния, не
  задетая проёмом, не регионится и не дублируется; в ветке «не изменилась»
  временный регион удаляется. Задокументированное отклонение.
- Счёт QC/QR — по объектам сессии (реестр created-objects), а не селекцией по
  слою (VBA цепляет старые плитки прошлых прогонов в bbox). Отклонение.

## Что меняется для пользователя

- Покрытие [доска/плитка] выбирается и в Const (радио в DCL разблокировано в
  обоих режимах; в командном вводе Const — вопрос `Покрытие [d/p] <d>:`).
- Порядок командных вопросов (Const и Var): радиус → покрытие → сдвоенные лаги
  (вопрос ПРОПУСКАЕТСЯ при «p», шаг = 0) → далее как было. В DCL при «плитка»
  поле «Шаг сдв. лаг» гаснет и форсится 0.
- В режиме «плитка» на `плиткаvb` появляются плитки: целые — полилинии, обрезанные
  контуром/проёмами — регионы. `OPORCLEAN` их убирает (XData). В таблице QC/QR —
  реальные счётчики. Лог: «плитки: целых=N, обрезанных=M», OPORDUMP — строка S4.
- Режим «доска» не меняется вовсе (QC/QR остаются «0»).

## Реализация

1. **`opor-config.lsp`**: версия `"3.9-s4-tiles"`; допуски VBA:
   `*opor-vba-tile-outside-area-tolerance*` 0.001 (cregarea<0.001),
   `*opor-vba-tile-trim-area-tolerance*` 1.0 (plarea−cregarea≤1),
   `*opor-vba-tile-hole-zero-area-tolerance*` 0.0001 (areaNew<0.0001).
2. **`opor-tiles.lsp`** (заглушка → код): `opor-tile-polyline` (замкнутая
   полилиния по 4 углам, слой плиткаvb, xtype `tile`), `opor-tile-region`
   (AddRegion c guard, vlax-invoke), `opor-tile-center` (середина bbox),
   `opor-tiles-run session` — весь конвейер: ковёр по индекс-диапазонам сетки
   из сессии (`grid-p-index-range` — позиции вдоль vec с шагом step-x,
   `grid-v-index-range` — вдоль perp с шагом step-y; плитка (i,j) = прямоугольник
   от base+vec·i·sx+perp·j·sy со сторонами vec·sx/perp·sy), классификация по
   контуру, резка регионами (Explode-распад через `opor-variant-list`),
   вычитание проёмов (с Б-фиксом), счёт → session `'tile-whole-count` /
   `'tile-trimmed-count`. Elevation контура/проёмов на время фазы — 0
   (сохранить/вернуть). Все созданные объекты — XData (register-created;
   регионы — xtype `tile-region`), удаляемые — delete + unregister.
3. **`opor-ui.lsp`**: Const-ридер: после радиуса `(setq tile-mode
   (opor-ui-read-tile-mode))`, дв. лаги только при "d" (иначе 0), session-set
   'tile-mode. Var-ридер: вопрос покрытия переносится ДО дв. лаг; дв. лаги при
   "p" не спрашиваются (0).
4. **`opor-dcl.lsp`**: sync: `cov_d`/`cov_p` активны всегда; `dbllag` активен
   только при cov_d. accept: при cov="p" `dbl` форсится 0.0 (до валидации).
   `opor-dcl-apply-common`: session-set 'tile-mode (Const-путь сейчас его не
   пишет — фикс); из var-пути дублирующий set убрать.
5. **`opor-core.lsp`**: в Const- и Var-ранах после успешного `opor-grid-build`:
   `(if (= (opor-session-get 'tile-mode) "p") (opor-tiles-run *opor-session*))`;
   в финальные логи — `(opor-tiles-log-text)` (", плитки: целых=N, обрезанных=M"
   при p, иначе "").
6. **`opor-tables.lsp`**: QC/QR из сессии (`itoa` счётчиков, дефолт 0).
7. **`opor-dump.lsp`**: строка «S4 плитка: целых=…, обрезанных=…» (при p) в
   сессионный блок; типы tile/tile-region в свод попадают автоматически.
8. **`эталоны/README.md`**: карточка S4 после прогонов; примечание, что с
   v3.9 в командном Const появился вопрос «Покрытие» (для перегона старых
   эталонов — Enter).

## Не входит

- ТЗ п.8 (сетка по шагу опор, плитка отдельно) — отдельный этап после переноса.
- Точный крепёж плитки «по формату» — временная формула v3.4 остаётся.
- Мультиконтур, вспом. инструменты.

## Риски и краевые случаи

- `vla-Boolean` мутирует вызывающий регион — регион контура создаём заново на
  каждую плитку (как VBA). Все COM-вызовы под `vl-catch-all-apply`; Explode
  разворачиваем `opor-variant-list` (пустые safearray уже обезврежены в S5).
- Elevation контура ≠ 0 ломает Boolean в плоскости — временно обнуляем (VBA
  делает то же на входе a_main).
- Индекс-диапазоны порта шире VBA на ±3 запасных — лишние плитки рождаются вне
  контура и сразу удаляются (числа не меняются, объекты не остаются).
- Порядок вопросов Var в логах меняется (покрытие до дв. лаг) — эталонная
  процедура обновляется в README эталонов.
