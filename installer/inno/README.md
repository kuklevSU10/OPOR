# Установщик OPOR на Inno Setup

Готовый `.exe` для передачи заказчику. Заменяет прежнюю связку
`INSTALL_OPOR.cmd` + `install_opor.ps1` (они оставлены в `installer/`
как рабочий запасной вариант, логика размещения файлов та же).

## Как пересобрать

Нужен [Inno Setup 6](https://jrsoftware.org/isdl.php).
Сборщик поддерживает как системную установку в `Program Files`, так и
пользовательскую установку `winget` в `%LOCALAPPDATA%\Programs\Inno Setup 6`.

Из каталога `installer/inno` запустить:

```powershell
.\build_installer.ps1
```

Скрипт сам берёт канонические файлы из корневой `OPOR/`, проверяет обязательную
DWG-библиотеку, формирует `payload` и получает текущую версию (сейчас 3.35.0) из
`*opor-version*` в `OPOR/opor-config.lsp`. Ручное копирование payload и правка
версии в `.iss` больше не нужны. Во временной staging-папке находятся 27 файлов:
bootstrap и 26 файлов `OPOR`; установленный bundle содержит ещё сгенерированный
`PackageContents.xml`, итого 28.

Для проверки состава без компиляции:

```powershell
.\build_installer.ps1 -StageOnly
```

Удалить временные staging-файлы:

```powershell
.\build_installer.ps1 -Clean
```

При полной сборке нужен `ISCC.exe`; результат —
`output\OPOR_Setup_<версия>.exe`. По умолчанию временный payload удаляется после
успешной компиляции; `-KeepPayload` сохраняет его для ручной проверки.

## Выбор версий AutoCAD

Установщик находит установленные версии AutoCAD в реестре
(`HKLM\SOFTWARE\Autodesk\AutoCAD\R*` и то же в `HKCU`, обязательно
в 64-битной ветке — установщик 32-битный, без `HKLM64` он смотрел бы
в `WOW6432Node` и не нашёл бы ничего) и показывает их списком с
галочками. По умолчанию отмечены все.

Bundle физически один и лежит в одной папке — ограничение по версиям
задаётся не расположением файлов, а манифестом: на каждый отмеченный
релиз пишется свой блок `<Components>` с `SeriesMin`/`SeriesMax`,
равными коду релиза. В неотмеченные версии AutoCAD плагин не грузится.

Поэтому `PackageContents.xml` **не копируется готовым файлом**, а
генерируется кодом установщика на шаге `ssPostInstall`. Правка манифеста
в `installer/autoload/PackageContents.xml` на сборку через Inno больше
не влияет — он остался только для ручной установки и старого PS-скрипта.
Список команд задаётся в функции `CommandsBlock` внутри `.iss`.

Коды релизов берутся из реестра как есть, а не из таблицы, поэтому
неизвестная будущая версия всё равно определится и попадёт в список
(подписью будет `AutoCAD (R25.2)` и т.п.). Таблица `ReleaseToName`
влияет только на подпись.

Важно: фильтр работает по релизу, а не по продукту. Один релиз — это
и AutoCAD, и вертикальные продукты на его основе (например, R24.0 — это
AutoCAD 2021 и Civil 3D 2021). Разделить их галочками нельзя.

При тихой установке диалога нет, поэтому включаются все найденные
версии. Если AutoCAD не найден вообще, манифест пишется без ограничений
по релизам — плагин заработает, когда AutoCAD появится.

## Что делает установщик

- Ставит bundle в **профиль пользователя**:
  `%APPDATA%\Autodesk\ApplicationPlugins\OPOR.bundle`.
  AutoCAD сканирует эту папку наравне с машинными, поэтому права
  администратора и запрос UAC в обычном сценарии не нужны.
- **Ищет и удаляет все прежние копии** во всех папках, которые сканирует
  AutoCAD (`%APPDATA%`, `%PROGRAMDATA%`, `Program Files`,
  `Program Files (x86)`), включая мусор прежнего установщика:
  `OPOR.bundle.backup-*` и брошенные `OPOR.bundle.installing-*`.
  Иначе AutoCAD может поднять старую версию, и человек решит, что
  обновление не сработало.
- Машинные копии без администратора не удаляются. Молча это оставлять
  нельзя, поэтому установщик один раз спрашивает и, при согласии,
  удаляет их с повышением прав (одно окно UAC на все папки сразу).
  При отказе — показывает точный список папок для ручного удаления.
- Если плагин уже установлен, при повторном запуске предлагает выбор:
  **переустановить/обновить** или **удалить**.
- Не даёт ставить при запущенном AutoCAD (проверяет `acad.exe`
  и `acadlt.exe`) — иначе файлы залочены.
- Регистрируется в «Установка и удаление программ» как `OPOR <версия>`;
  удаление штатное, через Windows или `unins000.exe`.

## Тихая установка (для массовой раскатки)

```
OPOR_Setup_3.35.0.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART
```

Лог установки: добавить `/LOG="путь\install.log"`. В логе есть строки
`OPOR: ...` — целевая папка, найденные и удалённые прежние копии.

При запущенном AutoCAD тихая установка **прерывается** с записью в лог
(диалога «Повторить» в тихом режиме быть не может).

## При смене версии

Номер установщика автоматически выводится скриптом сборки из
`*opor-version*` в `OPOR/opor-config.lsp` и записывается во временный
`version.generated.iss`. Ручной `PackageContents.xml` используется только
альтернативными способами установки и на Inno-сборку не влияет.

`AppId` (GUID) менять **нельзя** — по нему Windows находит прошлую
установку для обновления и удаления.

## Что проверено

Историческими прогонами старой сборки на этой машине были проверены:

- чистая установка, установка поверх, удаление, повторная установка;
- удаление четырёх подставных «старых копий» разом — двух в профиле
  и двух машинных;
- после установки: 28 файлов, `opor.dcl` остался в CP1251,
  20 команд в манифесте, баланс скобок во всех 24 модулях,
  запись в «Установка и удаление программ».

Для текущего канонического кода 3.35 проверена полная сборка Inno Setup 6.7.3:
24 LSP, `opor.dcl`, DWG-библиотека и bootstrap берутся из актуальных исходников;
все 26 файлов папки OPOR совпадают со staging побайтово. Результат:
`output/OPOR_Setup_3.35.0.exe`, версия ресурсов 3.35.0. После установки нового
EXE остаётся обязательная live-проверка:
запустить обычный AutoCAD и вызвать `OPOR` напрямую без APPLOAD.
