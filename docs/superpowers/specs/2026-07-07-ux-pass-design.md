# UX-пасс панели OPOR (v3.7-ux-pass) — дизайн

Дата: 2026-07-07. Статус: одобрен («Да, ебаш»; развилки: слои = рабочий белый
список, точка/направление = Enter-авто + ручной клик).

## Запрос пользователя

1. При старте A/B видеть только рабочие слои (чужие гаснут) — удобно тыкать контур.
2. Проёмы не выбирать руками — автоопределение.
3. После выбора контура — центрировать экран на нём.
4. Промах при выборе начальной точки не должен отменять команду; видеть границы.
5. Понятные дефолты для начальной точки/направления (Enter = авто).

## Поведение (новый поток A/B)

A/B → `opor-layers-hide` (гаснет всё вне `*opor-visible-layers*` и текущего слоя)
→ выбор контура → зум на bbox контура +10% → `opor-detect-holes` (замкнутые
полилинии на «областиvb», все вершины внутри/на границе контура; лог «Проёмов
найдено: N») → форма «Ввод» (галка «скрыть лишние слои» УДАЛЯЕТСЯ — это теперь
автоматика) → (Const) список опор → точки с подсветкой контура (`vla-Highlight`):

- «Начальная точка сетки <Enter = угол у длинного ребра>» — промах мимо контура →
  princ-подсказка и ПЕРЕСПРОС (цикл); Enter → вершина длиннейшего прямого ребра;
  Esc → штатное прерывание (*error*: слои/вид/подсветка возвращаются).
- «Направление сетки <Enter = вдоль длинного ребра>» — Enter → вектор ребра от базы.
- «Точка вставки таблицы <Enter = справа от контура>» — Enter → правее bbox на
  max(1000, 15% ширины).

→ построение → как раньше: слои и вид возвращаются. Дополнительно возврат слоёв
ставится в хвост `opor-main` (покрывает отмену выбора контура/формы) и снятие
подсветки — в `opor-error-handler` (session-ключ 'highlighted-object).

## Части

- `opor-geometry.lsp`: `opor-detect-holes boundary` (рядом с opor-select-holes;
  старый селектор остаётся, но не вызывается), `opor-zoom-to-boundary boundary`.
- `opor-grid.lsp`: `opor-grid-default-base-dir boundary` → (база точка-направления)
  по длиннейшему прямому ребру (`opor-polyline-line-edge-pairs`); контур целиком
  из дуг → первая вершина + ось X.
- `opor-ui.lsp`: `opor-ui-highlight`, `opor-unhighlight-session`, переработка
  `opor-ui-pick-points` (цикл/дефолты/подсветка) — общая для DCL и командного пути.
- `opor-core.lsp`: hide до выбора контура, зум после, detect-holes вместо
  select-holes (оба режима), restore в хвосте opor-main.
- `opor-errors.lsp`: `opor-unhighlight-session` в error-handler.
- `opor.dcl` (CP1251, править питоном!) + `opor-dcl.lsp`: удалить галку hidelay.
- Версия `3.7-ux-pass`.

## Числа не меняются

Опоры/LENGTH/таблица не зависят от способа выбора проёмов/зума/подсветки.
Эталоны: процедура упрощается (вопрос «выберите проёмы» исчезает) — обновить
`эталоны/README.md`. Ввод точек кликом/координатами работает как раньше.

## Осознанные решения

- Проёмы всегда все (замкнутые, внутри контура); частичный выбор — YAGNI,
  при необходимости добавим ключ [Вручную].
- `opor-ui-base-point-ok-p` больше не используется pick-points (проверка инлайном
  с переспросом вместо alert+отмена) — функцию не удаляем.
- pick-points теперь всегда возвращает три точки; отмена — только Esc (через
  *error*, все возвраты гарантированы).
